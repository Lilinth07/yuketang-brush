## 🧪 这是一个纯 Vibe Coding 项目

本项目**从协议逆向到双击启动器，全部由 AI 辅助生成**，作者以「能跑就行」的体感推进，没有逐行审计过。

这意味着：

- 结构不保证优雅——很多地方是试出来的，不是设计出来的（比如那个 `cid` 参数实际要传 `classroom_id`，纯属踩坑踩出来的）；
- 边界情况没覆盖全：换个子域、平台改个接口、学校开了别的防作弊开关，脚本可能直接失败；
- 文档里的数字（85 个节点、12 小时、7.5 分钟）都来自一次真实运行，换课程后完全不同；
- 安全实践只做到「不把你的 cookie 和指纹提交到 git」这一层，再深的不敢保证。

**建议先读一遍 [`src/brush.mjs`](src/brush.mjs) 和 [`docs/PROTOCOL.md`](docs/PROTOCOL.md) 再运行**，确认它做的事在你的接受范围内。

欢迎 issue / PR，尤其是「我们学校的雨课堂跑不通」这种真实反馈——这类项目靠踩坑迭代，不靠设计。

## 特性

- **双击即用**：`启动.bat` 自动准备 Node 环境和依赖，全程按数字操作，不需要懂 npm
- **一次登录**：扫码或账号密码，登录态存在本地浏览器配置目录，下次直接复用
- **参数全自动**：只要粘贴课程 URL，`course_id` / `sku_id` / `sign` / 设备指纹 `cc` 全部自动发现，无需手填
- **实时进度**：单行刷新进度条，带 ETA、当前节点、成功/跳过/失败状态
- **节点级日志**：每个任务节点同时写 `人类可读 .log` 和 `结构化 .jsonl`
- **断点续跑**：已完成的节点自动跳过，中断后重跑不会重复上报
- **演练模式**：`--dry` 只算计划不发任何请求
- **多课程**：课程库放多门课，随时切换，菜单里带 `▶` 标记当前课程
- **零硬编码**：代码里没有你的账号、课程、设备信息

## 作业 / 测验

视频是纯接口操作，作业不是。这条链路上有两道坎：

1. **题干字体加密** —— DOM 里读出来是 `19、2007-2008肢户城压司贷那某筑米修…`，靠专属字体渲染成正常中文；
2. **提交有客户端风控** —— `/c27/anti-cheat/config` 里 12 个评分组，其中 `pointer.*` 那组专门抓「点击太像机器」。

第一条靠字形比对破，第二条靠**走接口不走 DOM** 绕。两条都解决了，所以现在作业也是全自动的。

### 入口

菜单里选 **`[6] 作业 / 测验`**，或者在命令行：

```bash
npm run brush -- --exam        # 刷完视频接着做作业
npm run brush -- --only-exam   # 跳过视频，只做作业
npm run exam -- --all --api    # 等价的独立命令
```

第一次进这个菜单会先问你配不配 AI（不配也能用「批量提交已有答案」）。所有 AI 相关设置都在这个子菜单里，主菜单没有单独入口：

```
  作业 / 测验  ·  示例课程

  AI      已配置 · deepseek-chat

  [1] 列出所有作业
  [2] 模型自动答题并提交
  [3] 批量提交（已有答案的作业）
  [4] 导出某份题目
  [5] 配置 AI
  [0] 返回
```

### 三步

```bash
# 1. 看有哪些作业
npm run exam -- --list

# 2. 导出题目成 markdown（同时生成答案模板）
npm run exam -- --leaf 90000003

# 3. 把答案填进 out/answers-90000003.json，再提交
npm run exam -- --leaf 90000003 --fill --dry      # 先演练：只算计划不发请求
npm run exam -- --leaf 90000003 --fill --api      # 接口直提（推荐）
```

### 提交方式：没有“交卷”，逐题即完成

抓包发现作业**没有独立的交卷接口**。页面上的“提交”按钮调的还是 `problem_apply`，提交的是当前这一题：

```json
POST /mooc-api/v1/lms/exercise/problem_apply/
{"classroom_id":32368227,"problem_id":76298734,"answer":[""]}
```

也就是说：**每道题点下选项就是提交，全部答完自动变“已提交”**。没有第二步。分数是异步批改的，`my_content_score` 会先保持 `-1`，过一阵才出分。

所以推荐直接用接口模式：

```bash
npm run exam -- --leaf 90000003 --fill --api
```

| 对比 | UI 填涂（`--manual`） | 接口直提（`--api`） |
|---|---|---|
| 风控分 | pointer 组 55 分，触发轨迹验证码 | **segment=0，完全不触发** |
| 速度 | 每题约 0.6 秒 + 人工 | 每题约 2 秒，全自动 |
| 稳定性 | 弹窗/遮罩/验证码都可能挡 | 只要 cookie 有效就行 |
| 限制 | — | 连续提交会撞 429，要放慢 |

实测：`--api` 连提 18 题，风控分一直是 0；到第 19 题才开始 429 限流。所以脚本里每题间隔 1.3~2 秒，遇到 429 会跳过并提示。

### 还想用 UI 的话

`--manual` 保留着：填涂完把窗口交给你。但既然点选项本身就是提交、而且会触发 pointer 风控，**除非接口挂了，否则没必要用**。

### 批量

```bash
npm run exam -- --all --api             # 所有有答案的作业，逐个接口直提
```


```json

  "1": "C",
  "2": "B",
  "4": "ABD"
}
```

### 字体是怎么破的

抓包发现：字体文件每次请求都不一样（`exam_font_<hash>.ttf`），但**文件大小恒定 690744 字节**。拆开看：

| 表 | 两次请求 |
|---|---|
| `glyf`（字形库） | **md5 完全相同** |
| `cmap`（编码映射） | 每次都变 |

也就是字形库固定，只重排了 `unicode → glyph_id` 的映射。配合 `post` 表无字形名，只能走形状比对：

1. 用 Playwright 的 canvas 把加密字形渲染成位图；
2. 用 **SimHei** 渲染 GB2312 全字库（6768 字）作为候选；
3. 双方都裁到墨迹包围盒、缩放到 32×32，算 IoU，取最高分。

实测 SimHei 与加密字形平均相似度 0.924，Top1 准确率约 **87%**。映射按 `glyf` 的 md5 缓存在 `out/glyph-map.json`，**首次约 18 秒，之后秒解**——因为字形库没变，只是编码换了。

还原出来的文本会有形近字错误（`卮/危`、`面/而`、`侪/济`），但句子语义完整，读题不受影响。

### 已知行为

- 平台会记住「答了但没提交」的草稿，再次进入会弹「刚刚答完的习题还没有提交」——工具会自动点「先不用了」，否则遮罩会挡住所有点击；
- 提交前会检查提交按钮是否置灰（有题没答时是灰的）；
- `--dry` 只填不提交，适合先确认题目对不对。

### 风险提示

- 提交走的是真实鼠标事件，但自动化环境仍可能被 `environment.webdriver.hit` 识别；
- 一旦触发挑战（hCaptcha），只能人工过，且有 10 分钟冷却；
- **建议先拿一个作业跑通再批量**，别一晚上清空所有作业——这比视频显眼得多。

## 工作原理（简述）

1. 登录后从课程 URL 解析 `classroom_id`，拉取章节树，挑出所有 `leaf_type=0` 的视频节点；
2. 对每个节点查一次进度接口，已完成的直接跳过；
3. 未完成的：先发 2 条探测事件拿到视频时长，再按「每 5 秒一条、时间戳连续递增」生成一批事件，一次性 `POST` 到进度上报接口；
4. 回查完成度，达标即下一个，没达标补发一轮。

不下载视频、不解码、不需要保持播放。完整协议（字段含义、事件序列、验证实验）见 [`docs/PROTOCOL.md`](docs/PROTOCOL.md)。

## 常见问题

**Q：提示「登录态已失效」**
重新 `npm run setup`。登录态通常能管几天到几周，换网络环境可能提前失效。

**Q：`setup` 卡在「抓取设备指纹」**
如果那节课你已经看完了，视频不会自动播放，就抓不到心跳报文。换一节没看过的，或者按提示手动从 F12 里抄 `cc`。

**Q：课程 URL 从哪来**
浏览器打开课程 → 进入「学习日志」或课程页面 → 复制地址栏整条 URL。

**Q：能不能不开浏览器**
`setup` 必须开（要扫码、要抓指纹）。之后 `npm run brush` 是纯 HTTP，不开浏览器。

**Q：跑完发现还有节点没完成**
`npm run verify` 看清单，然后 `npm run brush -- --only <id>` 单独补。

**Q：会不会被发现**
这个工具只处理进度上报，不改变任何前端行为记录。但**短时间内完成远超正常学习时长的内容，在教师端数据里是可见的**。自行判断风险。

**Q：`.profile` 和 `config.local.json` 能提交吗**
**不能。** 里面有 cookie 和设备指纹。`.gitignore` 已经排除，别手滑 `git add -f`。
