## 🧪 这是一个纯 Vibe Coding 项目

本项目**从协议逆向到双击启动器，全部由 AI 辅助生成**，作者以「能跑就行」的体感推进，没有逐行审计过。

这意味着：

- 结构不保证优雅——很多地方是试出来的，不是设计出来的（比如那个 `cid` 参数实际要传 `classroom_id`，纯属踩坑踩出来的）；
- 边界情况没覆盖全：换个子域、平台改个接口、学校开了别的防作弊开关，脚本可能直接失败；
- 文档里的数字（85 个节点、12 小时、7.5 分钟）都来自一次真实运行，换课程后完全不同；
- 安全实践只做到「不把你的 cookie 和指纹提交到 git」这一层，再深的不敢保证。

**建议先读一遍 [`src/brush.mjs`](src/brush.mjs) 和 [`docs/PROTOCOL.md`](docs/PROTOCOL.md) 再运行**，确认它做的事在你的接受范围内。

欢迎 issue / PR，尤其是「我们学校的雨课堂跑不通」这种真实反馈——这类项目靠踩坑迭代，不靠设计。

## 特性

- **双击即用**：`启动.bat` 自动准备 Node 环境和依赖，全程按数字操作，不需要懂 npm
- **一次登录**：扫码或账号密码，登录态存在本地浏览器配置目录，下次直接复用
- **参数全自动**：只要粘贴课程 URL，`course_id` / `sku_id` / `sign` / 设备指纹 `cc` 全部自动发现，无需手填
- **实时进度**：单行刷新进度条，带 ETA、当前节点、成功/跳过/失败状态
- **节点级日志**：每个任务节点同时写 `人类可读 .log` 和 `结构化 .jsonl`
- **断点续跑**：已完成的节点自动跳过，中断后重跑不会重复上报
- **演练模式**：`--dry` 只算计划不发任何请求
- **多课程**：一个配置里可以放多门课
- **零硬编码**：代码里没有你的账号、课程、设备信息

## 快速开始

### 方式一：双击（推荐，不需要懂命令行）

1. 点右上角 **Code → Download ZIP**，解压到任意文件夹（**路径别有中文和空格**）
2. 双击 **`启动.bat`**
3. 窗口会自己准备环境 → 然后出现菜单 → 按数字选就行

第一次用没有课程，选 **1** 会引导你：

## 日志

每次运行在 `out/logs/` 下生成两个文件，**互不覆盖**：

```
out/logs/brush-10000001-2026-10-23T21-23-42.log     人类可读
out/logs/brush-10000001-2026-10-23T21-23-42.jsonl   一行一条 JSON
```

记录的任务节点：

| 阶段 | 节点 | 内容 |
|---|---|---|
| `init` | 课程 / 参数 / 日志路径 | 本次运行的完整上下文 |
| `auth` | 登录态校验 | uid、姓名、学校 |
| `tree` | 章节树加载 | 节点总数、视频数、缓存文件 |
| `plan` | 待处理清单 | `--only` 命中数 |
| `run` | `lesson:begin` | 节点 ID、标题、所属章节 |
| | `lesson:state` | 现有完成度、观看时长 |
| | `lesson:skip` | 已完成，跳过 |
| | `lesson:probe` | 探测到的视频时长 |
| | `lesson:post` | 上报条数、HTTP 状态、耗时 |
| | `lesson:verify` | 回查的完成度 |
| | `lesson:retry` | 未达标时的补发 |
| | `lesson:done` / `lesson:fail` | 最终结果 |
| `verify` | `verify:complete` | 全量完成率、累计时长 |
| `summary` | 运行汇总 | 计数、请求数、耗时 |

`npm run logstat` 把 jsonl 汇总成可读报告：

## 工作原理（简述）

1. 登录后从课程 URL 解析 `classroom_id`，拉取章节树，挑出所有 `leaf_type=0` 的视频节点；
2. 对每个节点查一次进度接口，已完成的直接跳过；
3. 未完成的：先发 2 条探测事件拿到视频时长，再按「每 5 秒一条、时间戳连续递增」生成一批事件，一次性 `POST` 到进度上报接口；
4. 回查完成度，达标即下一个，没达标补发一轮。

不下载视频、不解码、不需要保持播放。完整协议（字段含义、事件序列、验证实验）见 [`docs/PROTOCOL.md`](docs/PROTOCOL.md)。

## 常见问题

**Q：提示「登录态已失效」**
重新 `npm run setup`。登录态通常能管几天到几周，换网络环境可能提前失效。

**Q：`setup` 卡在「抓取设备指纹」**
如果那节课你已经看完了，视频不会自动播放，就抓不到心跳报文。换一节没看过的，或者按提示手动从 F12 里抄 `cc`。

**Q：课程 URL 从哪来**
浏览器打开课程 → 进入「学习日志」或课程页面 → 复制地址栏整条 URL。

**Q：能不能不开浏览器**
`setup` 必须开（要扫码、要抓指纹）。之后 `npm run brush` 是纯 HTTP，不开浏览器。

**Q：跑完发现还有节点没完成**
`npm run verify` 看清单，然后 `npm run brush -- --only <id>` 单独补。

**Q：会不会被发现**
这个工具只处理进度上报，不改变任何前端行为记录。但**短时间内完成远超正常学习时长的内容，在教师端数据里是可见的**。自行判断风险。

**Q：`.profile` 和 `config.local.json` 能提交吗**
**不能。** 里面有 cookie 和设备指纹。`.gitignore` 已经排除，别手滑 `git add -f`。
